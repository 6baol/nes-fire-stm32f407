# 完善方案（基线 v0.20，可调参数集中管理）

本文是后续工作的固定基线。每条方案末尾标注可调参数，改动这些参数不需要重做架构。
所有条目都按“本地构建 + 仿真/回归验证”推进，上板与烧录仍需用户明确授权。

## 0. 现状与硬约束

| 约束 | 当前值 | 影响 |
|---|---|---|
| 外扩 SRAM arena | 普通 640 KiB @0x6C060000，MMC5 896 KiB @0x6C020000 | 单个 ROM 上限，无法靠改代码突破，只能改板或分块流式解码 |
| FatFs 长文件名 | `FF_USE_LFN 0` | **换卡即用的最大阻塞点**：只能看到 8.3 短名 |
| FatFs 目录遍历 | `f_readdir` 已编译可用（`FF_FS_MINIMIZE 0`） | 可直接扫描，无需新增底层 |
| 固件体积 | Code 98,780 + RO 56,348 字节（约 152 KiB / 1 MiB） | 有充足空间，LFN 约 5–8 KiB 可接受 |
| 帧率 | 逻辑约 39 fps（MMC5 RPG），画面约 20 Hz | 体验层面第一优先级 |
| 存档 | `NES/SAVES/<CRC32>.SV0/.SV1`，8 KiB ×2 | 不可读、不可找、不可迁移 |

## 1. P0 实时性（目标：逻辑 60 fps / 画面 ≥30 Hz）

1. **PPU 出图去冗余**：`do_scanline_and_draw` 目前每行都整行重算。改为 tile 级脏标记 + 行内 tile 缓存，未变化的 tile 直接从上次结果拷贝。
2. **提交分块**：按 DWT 预算把整帧提交拆成多次，避免单帧一次性 30 ms 卡顿；欠账仍沿用现有调度器补帧机制。
3. **APU 合成降本**：混音表改为定点整数表 + 每半缓冲一次重采样；MCU5/FDS 扩展音频走独立预算。
4. **TE 同步**：读 LCD tearing effect 信号，只在消隐窗口提交，消除撕裂。

可调：每帧绘制预算（当前相当于 ~35 ms 上限）、画面提交下限（20 Hz）、脏块阈值。

## 2. P0 SD 直接放 ROM（去掉电脑预处理）

目标：用户把 `*.nes` / `*.fds` 原样拷进 `F:\NES\`，游戏名保持原有大小写、空格和括号，开机即可见并可玩。

1. **开启长文件名**：`FF_USE_LFN 2`（静态缓冲，避免栈溢出）、`FF_MAX_LFN 255`。`FF_CODE_PAGE` 保持 437；非 ASCII 文件名降级为短名或 `GAME n`，不做 CP936。
2. **新增目录扫描**（`nes_library.c`）：`f_opendir("0:/NES")` + `f_readdir`，忽略目录与不支持扩展名，扩展名大小写不敏感，收集 ≤64 项。
3. **上机校验**（新增 `nes_import.c`，从 `tools/embed_roms.py::validate` 移植）：
   - 读 16 字节头 + `f_size`；校验大小 = `16 + PRG*16384 + CHR*8192`、Mapper 在支持集内、PRG/CHR 逐 Mapper 限制、`f_lseek` 读复位向量、arena 上限。
   - 失败不中断扫描，记录原因，在菜单可查看（如 `MAPPER 9 UNSUPPORTED`）。
4. **NES 2.0 头归一化**：满足 `normalize()` 子集条件时在 RAM 内改写 16 字节头后再交给 `Nes_Load`；CRC 仍按卡上原始字节计算。
5. **索引不再必需（v0.20 已实现）**：`LIBRARY.IDX` 只作为旧卡的显示名回退；固件写 `NES/INDEX.CCH`
   （目录快照 + 每项名称/Mapper/大小），命中则跳过逐项探测。见 [sd_scan_v0.20.md](sd_scan_v0.20.md)。
6. **封面可选**：`NES/<同名>.COV` 存在则用，缺失回退到原生图形，菜单不再依赖电脑生成的编号封面。
7. **PC 工具降级**：`prepare_sd.py` 只负责可选的封面/元数据打包与 CI 造包，不再是使用前提。

可调：`NES_LIBRARY_MAX`（默认 64）、扫描根目录列表、标签最大长度（46）、是否要求 CRC 校验（默认是）。

验收：原样拷入 12 个带括号和空格的 ROM，菜单名称正确、逐款可启动；不支持 Mapper 的给出明确原因；无 `LIBRARY.IDX` 时功能完整；旧索引仍可回退使用。

## 3. P0 存档可见（用户能找到、能看懂、能迁移）

1. **命名改为可读**：`NES/SAVES/<ROM 基名>.SAV`，上一版为 `<ROM 基名>.BAK`；元数据放 `<ROM 基名>.SVH`（ROM CRC32、大小、写入计数）。
2. **格式保持原始 8 KiB PRG-RAM**：`.SAV` 就是裸 8 KiB，PC 上可被常见模拟器直接识别；校验信息放 `.SVH`，不污染 `.SAV`。
3. **写入顺序**：先读旧 `.SAV` → 写 `.BAK` → 写新 `.SAV` → 回读校验 → 更新 `.SVH`，失败保留 `.BAK` 并在菜单显示原因。
4. **菜单可见**：游戏列表每项显示 `SAV` 标记；新增存档管理页（列表：名称、8 KiB、写入计数；操作：删除单项 / 全部删除 / 立即保存）。
5. **保存时机**：返回菜单、切换 ROM、管理页手动保存。没有电池，掉电丢失仍需在文档中明示。

可调：是否保留双槽（默认：`.BAK` 一份）、是否启用 `.SVH`（关闭后单文件模式，无法校验）、基名最大长度。

验收：PC 上打开 SD 能看到 `Super Mario Bros. 3.SAV` 并导入其他模拟器；固件冷启动恢复一致；删除单项不影响其他游戏；`.BAK` 在损坏时可回滚。

## 4. P1 时序精度

1. 调度从“按扫描线批量 `run6502(cycles*256)`”改为子扫描线（建议 8–16 dot 粒度），NMI/IRQ 在入口处按周期计。
2. PPU 补点级 sprite-0 hit、精灵溢出、`$2007` 读写抖动与 open bus。
3. MMC3 IRQ 由扫描线近似改为 A12 上升沿计数，并补各修订版差异。
4. APU 补 `$4017` frame sequencer 与 frame IRQ，DMC 独立验收。
5. FDS 由 ≤16 周期分片改为逐周期，补写盘（见 5.2）。

可调：调度粒度、IRQ 判定窗口、是否开启严格模式（严格模式仅用于测试）。

## 5. P1 Mapper 与功能

1. **Mapper 补全顺序**（按游戏覆盖面收益）：9/10（MMC2/4）→ 21/22/23/25/26/85（VRC2/4/6/7）→ 19（Namco 163）→ 67/69（Sunsoft）→ 33/48/79/90 → 232（Quattro）与 multicart。
2. **FDS 写盘与自动换面**：写保护解除 + 块级 CRC 回写，多面镜像自动切面。
3. **其二玩家手柄**：输入层抽象为 2 路，菜单可配置键位。
4. **即时存档**：整机状态（CPU/PPU/APU/Mapper/SRAM）序列化到 `.STA`，与 `.SAV` 分开管理。
5. **音频**：采样率可配置（11,025 / 22,050 / 32,000 Hz），加入低通与线性混音近似修正。
6. **加载器放宽**：NES 2.0 submapper≠0 的常用配置、trainer、四屏镜像、PAL 由“拒绝”改为“按支持能力接受或明确说明”。

可调：新增 Mapper 的启用开关、音频采样率、存档槽数量。

## 6. P2 工程与验证

1. 兼容性矩阵：逐款商业 ROM 的“标题/进入关卡/移动/音效/存档”冒烟脚本，结果进 `Tests/nes_output` 并纳入 CI。
2. 每轮构建保持 0 error / 0 warning；体积、Heap、栈水位记录进 `Release/manifest.json`。
3. 实机报告与本地仿真报告分开命名，不混用。

---

## 7. 推荐顺序

1. SD 直放 ROM（长文件名 + 目录扫描 + 上机校验）——用户侧收益最大，改动集中在 `ffconf.h` 与 `nes_library.c`。
2. 存档改名 + 菜单可见——工作量小，立刻可验证。
3. 实时性（tile 脏标记 + 分块提交 + TE）。
4. MMC3 A12 / APU frame IRQ。
5. Mapper 与即时存档。

每一步都单独出构建产物与回归记录，不合并提交。
