# Bullet Garden v0.4

基于野火 STM32F407 霸天虎 V2、4.3 寸 MCU 电容屏、HW-504 摇杆的首个可烧录版本。

已实现：480×800 竖屏、摇杆自动中心标定/滤波/径向死区、非阻塞按键、自动双列射击、小怪、三阶段 Boss、环形/瞄准扇形/旋转弹幕、碰撞、生命、炸弹、低速判定点、暂停、胜利/失败及重新开始。启动时运行 SRAM 自检、全屏填充测速。输入诊断页显示原始 ADC、中心值、向量及错误数。

**验证范围：Keil 全量编译与主机测试通过；v0.3 已完成实物 DAP 下载及完整读回校验，用户确认标题显示。摇杆方向、战斗 FPS 和输入延迟尚待验收。** Tests/output 的图像由真实 C 渲染器在模拟 LCD 上输出，用于界面核查，不是板上拍照。

## v0.4 实施与测量

v0.4 已下载并完整读回校验，用户实物反馈“明显顺滑了”。主要优化：O2、子弹按屏幕行建立空间索引、圆形先裁剪后绘制、状态栏降到 5 Hz、游戏显示目标 60 Hz、短预算分块绘制、按采样时间滤波与 6% 死区。

同板固定场景：普通场景 16→60 FPS，约 174 发 Boss 场景 4→60 FPS，256 发 Boss 压力场景 3→60 FPS。连续运行输入采样窗口约 502 Hz，最大间隔 3 ms。完整条件和边界见 `Release/性能优化报告_v0.4.md`，这些数字不代替所有场景和长期测试。

请烧录 v0.4；Release 中 v0.1～v0.3 保留供回溯。摇杆接线和 3V3 供电不变。

## 接线与首次上电

断电后按实物丝印连接：

| HW-504 | 霸天虎 V2 | 配置 |
|---|---|---|
| GND | GND | 共地 |
| +5V（电源正极丝印） | **3V3** | 按双电位器结构采用 3.3 V 激励；首次测量确认模拟输出范围 |
| VRx | **PA4** | ADC1_IN4，CN3 第 **25** 脚 |
| VRy | **PA6** | ADC1_IN6，CN3 第 **21** 脚 |
| SW | **PB7** | 上拉输入、按下为低，CN3 第 **23** 脚 |

PA6、PB7、PA4 是 CN3 同一侧连续的 21、23、25 针位，已按用户所附 2025 原理图核对。它们与摄像头接口共用，使用时保持摄像头接口空置；不需要为摇杆拔下 J77/J78，如果此前仅为旧摇杆接法拔下，可在断电后恢复原状态。实际 PCB 修订不同须核对丝印。不要以 5 V 激励摇杆后把模拟输出直接送入 ADC。屏幕按原工程连接，下载器按原板 SWD 接线。

v0.3 使用上述集中接线，并修正 ILI9806G 的 FSMC 读时序。v0.1 使用旧引脚；v0.2 未包含本次黑屏修复，请下载 v0.3。

1. 用 Keil 下载 `Release/BulletGarden_v0.4.hex`，或者打开 `Project/Fire_F407ZG.uvprojx` 编译下载。HEX 自带地址；若使用 BIN，Flash 起始地址为 **0x08000000**。
2. 复位，释放摇杆并等待 `STICK READY`。自动标定需 256 对稳定采样，理想约 0.5 秒，实际由主循环负载决定。
3. 标题界面按 KEY1 进入输入诊断，检查两轴中心约为 2048、回中向量为零、推向对角线时长度不超过 1。
4. 诊断页按 KEY1 重新标定；按 SW/KEY2 返回标题。
5. 标题页按 SW、KEY2 或点触屏幕开始。

若停留在标定状态，先检查 3.3 V/共地、摄像头接口空置以及 PA4/PA6 模拟接线，再观察原始 ADC；软件要求中心值在 1000～3100 且 256 对样本的每轴跨度不超过 180。此检查不能证明模块没有断线：悬空模拟引脚的表现取决于实物。

`CALIBRATING` 表示 X/Y 两轴回中标定，与是否按下 SW 无关。SW 未按下时应读到 PB7=1，程序按下状态=0。本次实物排查发现摇杆接 5V 时，松杆中心约 X=3190、Y=3275，导致标定不通过。请断电后将模块丝印“+5V”的电源脚接到开发板 3V3；该丝印不代表本项目要接 5V。不要通过放宽标定范围掩盖供电错误。

## 操作

| 状态 | 操作 | 行为 |
|---|---|---|
| 标题 | KEY1 | 输入诊断 |
| 标题 | SW / KEY2 / 点触屏幕 | 已完成标定时开始 |
| 诊断 | KEY1 | 释放摇杆并重新标定 |
| 诊断 | SW / KEY2 / 点触屏幕 | 返回标题 |
| 游戏 | 摇杆 | 连续比例移动；自动射击 |
| 游戏 | 按住 KEY1 | 低速移动并显示红白判定点 |
| 游戏 | SW | 使用炸弹，一次按下触发一次 |
| 游戏 | KEY2 / 点触屏幕任意位置 | 暂停/继续 |
| 胜利/失败 | SW / KEY2 / 点触屏幕 | 返回标题 |

初始 3 条生命、2 枚炸弹；受击后无敌约 2 秒。Boss 在开始后约 15 秒出现，随血量切换三种弹幕，击破后通关。自机碰撞半径 3 px；敌弹半径叠加计算。子弹离屏回收，弹池满时丢弃新弹并计数。

## 编译与测试

### DAP 下载

2026-11-16 已通过 Fire CMSIS-DAP / SWD 下载 v0.3，独立逐字节读回校验 42952 字节全部一致。板上确认 LCD ID=0x9806、480×800、背光开启、SRAM/触摸初始化通过；用户已确认显示 BULLET GARDEN 标题。摇杆操作和战斗帧率仍需实测。

本次排查发现 Keil 虽返回 Verify OK，独立读回的 Flash 内容却与发布文件不一致。后续下载脚本已改用 pyOCD，禁止自动解锁，只擦除固件覆盖的扇区，写入后逐字节读回比对发布 BIN；写入前备份所覆盖扇区到工作区 backups。

```powershell
.\Game\build.ps1
.\Game\flash_dap.ps1
# 只校验，不重新烧录：
.\Game\flash_dap.ps1 -VerifyOnly
```

pyOCD 环境位于工作区 `.tools/dap`，使用用户资料内的离线 STM32F4xx_DFP.2.15.0.pack。脚本为 `tools/dap_flash.py`；校验报告为 `Release/dap_download_v0.3.json`，板上状态为 `Release/board_status_v0.3.json`。旧 Project/download.log 只保留 Keil 操作记录，不能替代独立读回校验。

黑屏修复：FSMC 原读写共享快速时序，不满足 ILI9806G ID 读取要求（厂家手册第 408 页：ID 读周期至少 160 ns、RD 高至少 90 ns、RD 低至少 45 ns）。现启用 ExtendedMode，读 AddressSetup/DataSetup 各为 0x3F，写入保持 0x04，并延长硬复位后等待。保留原始 LCD ID 变量供 SWD 排查。

本机 uVision 只注册了 Arm Compiler 6.24，项目已从旧 AC5 选择迁移到 **AC6.24**，保留原 ARM 汇编启动文件。使用其他 Keil 安装时，在 Target 设置中选择本机可用的 AC6；无需修改全局工具配置。

PowerShell 全量编译并生成发布文件：

```powershell
.\Game\build.ps1
# 非默认 Keil 安装路径：
.\Game\build.ps1 -KeilExe 'C:\YourKeil\UV4\UV4.exe'
```

脚本严格检查 0 errors/0 warnings 和 HEX 更新时间，通过后复制 HEX，并调用 fromelf 导出 BIN。编译日志：`Project/build.log`。本机已验证全量构建；编译报告约 42 KiB Flash、22 KiB RAM。

WSL 中运行主机测试（需要 C 编译器和 AddressSanitizer/UndefinedBehaviorSanitizer）：

```powershell
wsl --exec sh /mnt/d/Project/BA_Game/Game/Tests/run_host_tests.sh
```

测试覆盖状态切换、暂停、标定门控、正常/低速/对角移动限幅、扫掠碰撞、无敌、炸弹、三种弹幕、弹池溢出、200000 步运行、LCD 窗口边界、局部重绘与完整重绘像素一致性，以及模拟 ADC 的顺序采样、中心标定、死区、对角限幅、转换超时恢复、偏置拒绝。结果写入 `Tests/output/results.txt`，预览原图为同目录的 PPM；PNG 是对应转换副本。

## 模块与实现选择

- `User/game/game_core.*`：不依赖 HAL 的固定 60 Hz 游戏逻辑、静态弹池、关卡及碰撞。
- `User/game/game_app.*`：DWT 调度、最多补算 4 步、20 ms 去抖、触摸轮询、非阻塞蜂鸣器和串口统计。
- `User/joystick/bsp_joystick_hw.h`：集中定义两轴 ADC 引脚/通道与 SW 输入引脚，驱动和按键读取共享同一份配置。
- `User/joystick/bsp_joystick.*`：两路 ADC 分阶段采样。轮询 EOC 标志，不等待转换；每对采样间隔目标 2 ms。首版采用软件触发，后续可换定时器+DMA。
- `User/render/renderer.*`：冻结一份游戏快照，标记旧/新对象覆盖的 16×16 脏块，每次以一块推进，主循环按约 500 μs 绘制预算让出执行。每块在片内 512 B 缓冲内重建背景并合成全部相交对象，不使用完整外部帧缓冲。
- `User/game/game_config.h`：轴反向、死区、弹池、刷新频率、渲染批量和 SRAM 自检开关。

运行中不调用原来的阻塞 `Key_Scan()`。LCD MMIO/DWT 已补充 volatile；未知 LCD ID 时停止启动而不调用空指针。触摸中断仅置标志，游戏在前台限频轮询；触摸调试打印关闭，对点数和坐标数组容量做检查。

触摸只识别“点按”动作，当前不依赖屏幕坐标映射；没有方向选择菜单。若推杆方向相反，修改 `GAME_JOY_INVERT_X` / `GAME_JOY_INVERT_Y` 后重新编译。若希望交换两轴，交换 VRx/VRy 的物理接线。

串口参数 **115200、8N1**。启动报告 LCD ID、HCLK、SRAM、触摸和全屏填充耗时；运行中每秒输出 `fps/draw/max/logic/over/adc/ready/err/bullets/drop`。运行统计使用 TXE 轮询逐字节发送，不调用阻塞 printf。

`draw` 是一份快照从开始到提交结束的墙钟耗时，包含分块之间的主循环工作；`max` 包含初始整屏绘制，可能明显大于日常局部刷新；`logic` 为单次逻辑更新最大耗时，`over` 为补算过载次数。标题/诊断故意降到约 5 FPS，战斗显示目标 60 FPS；实际以实物串口为准。

## 本版边界与下一步

本版没有音乐、素材文件加载、存档、显示 DMA、TE 同步或完整帧缓冲。外部 SRAM 只在启动测试，不存游戏状态；测试失败会显示 FAIL，但片内渲染仍可运行。分块提交不能保证无撕裂。显示方向与标题已上板确认；实际弹量、战斗刷新率和摇杆操作仍需验证，主机测试不替代这些验收。

原 Game 的完整备份保存在工作区 `backups/Game_before_implementation_20261116_093909.zip`。v0.4 已完成普通及 Boss 固定压力场景对比，详见 Release/性能优化报告_v0.4.md。其他弹型组合及长期表现仍以实物为准。
